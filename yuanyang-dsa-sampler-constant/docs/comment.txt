Subject: Round1: Public Comment: YuanYang.DSA — three wrong constants in the yuanyang-512 implementation, one of which leaks the secret key into the signature mean

Dear NGCC evaluation committee, dear YuanYang.DSA team,

The following errors are in the yuanyang-512 reference and optimized implementations. None of them
is in the specification; the -1024/-2048 implementations are correct on all three points.

Error 1 — fpr.h: fpr_yuanyang_inv_2sqr_large_sampler_sigma = 0x3ccc24a85.
  Decoded (43 fractional bits): 0.0018554 = 1/(2·(16η)²), η = 1.026.
  Required: 1/(2·(4η)²) = 0.029686 = 0x3ccc24a84f, since the wide sampler's RCDT table is built
  for 4η (sampler.c comment; Spec. Table 2, 4η = 4.104) and L = 4 in sign.c.
  The companion fpr_yuanyang_large_sampler_sigma = 0x8353f7ced917 decodes to 16.416 = 16η for the
  same reason. In yuanyang-1024 both constants decode to 4η.
  Consequence: the BerExp rejection almost always accepts. yuanyang_samplerz_large_zero returns −z0
  or z0+1 with probability 1/2 each: mean +0.458 instead of 0, variance 18.46 instead of 16.84.
  yuanyang_samplerz_large(μ) ignores most of frac(μ) (μ = 0.75 → mean 0.53).
  Security effect: E[x] = 0.458·𝟙 propagates through the presampler, so released signatures satisfy
  E[s] = (0.458/4)·Â·(𝟙,𝟙) + const, with Â the rounded Gram root of the signing key. Verified on the
  unmodified reference with two keys and 4·10^5 signatures each: the s1 mean, after removing the
  all-ones factor, regresses on the key's own a00 with slope 0.102 ± 0.011 and 0.113 ± 0.010
  (predicted 0.1145) and on the other key's a00 with slope 0.010 ± 0.010 and −0.011 ± 0.013. The
  mean is therefore a public, unbiased estimator of a00 (coefficient error 432/√N). Together with
  Error 0 below, a00·ā00 = σ² − 1 − (f f̄ + g ḡ), the element for which Fouque–Kirchner–Tibouchi–
  Wallet–Yu (EUROCRYPT 2020, ePrint 2019/1180) give a full key recovery from the public key. Exact
  recovery of f f̄ + g ḡ by rounding needs about 2^35 signatures in simulation; we did not perform it.
  Side effect: signature variance +3.2%, norm-rejection rate 15% instead of 2% per signature.
  Fix: set the constant to 0x3ccc24a84f and regenerate yuanyang_large_zero_berexp[] for 4η.

Error 2 — fpr.h: fpr_yuanyang_inv_2sqrsigma_sig (the Δ2 exponent constant) = 3701747757852.
  Decoded: 0.42084 = 1/(2·1.09²). Required: 1/(2σ_sig²) = 1.0274·10^-4 (σ_sig = 69.76); the stored
  value is exactly 2^12 too large. The -1024/-2048 constants are exact.
  Consequence: Δ2 rejects 4–11% of attempts (key-dependent) instead of the 1.5% (= 1 − 1/C) the
  specification predicts. After fixing sign-34-1 alone, Δ2 rejections rise to 0.4–1.1 per signature.
  Fix: divide the constant by 2^12 (or recompute it from σ_sig); apply together with the sign-34-1 fix.

Error 0 — keygen/perturbation.c, sigma_p_set_slot: Σp is built from B̂ᴴB̂ (column Gram matrix)
  instead of σ²I − B̂B̂ᴴ as in Spec. Algorithm 7, line 6. Already reported as ngcc.dev sign-34-1;
  listed here because Error 1 combines with it (see above) and Error 2 interacts with its fix.

Error 3 — Specification Table 3: σ_sig for yuanyang-2048 is given as 128.262. From η·σ =
  0.928 × 127.5 the value is 118.3, which is what the code uses (118.22) and what γ = 7641 implies.

Check after fixing Errors 0–2 (our patched copy of the reference): signature mean z ≤ 1.5,
secret-direction variance ratios 1.000 ± 0.001, s1 autocorrelation at noise level, 600/600
signatures verify. We suggest adding a signature-mean/variance self-test to the KAT suite so that
constants of this kind are caught automatically.
